1) Roles & Permissions
Roles table:
roles(id, name ENUM[superadmin, admin, moderator, user], permissions JSONB, createdAt)
Users table: extend with roleId foreign key.
Permissions JSONB example:
{
  "canManageUsers": true,
  "canManageContent": true,
  "canViewLogs": true,
  "canManageRoles": false
}
Default mapping:
Superadmin → all permissions.
Admin → manage users, manage content, view logs.
Moderator → manage content, view logs.
User → none (regular platform usage).
2) Authentication
Use existing OAuth (Google + Replit).
Restrict /admin/* to admin|superadmin|moderator.
If unauthorized → redirect to /unauthorized.
JWT stored in secure cookies.
3) Admin API (/api/admin/*)
Dashboard
GET /api/admin/dashboard → summary: total users, total trips, flagged reports.
Users
GET /api/admin/users?search= → list users with pagination + search.
PUT /api/admin/users/:id/role → change role.
GET /api/admin/users/:id → fetch single user details.
Content
POST /api/admin/media → upload image (drag/drop).
Store under /uploads/admin/.
DB: media_assets(id, fileUrl, ownerId, type, createdAt).
GET /api/admin/media?type=slides → list slide images.
PUT /api/admin/slides/:id → update/change slide image.
Roles
GET /api/admin/roles → list roles.
POST /api/admin/roles → create role with permissions JSON.
PUT /api/admin/roles/:id → update permissions.
Logs
GET /api/admin/logs?page= → paginated audit logs.
4) Audit Logging
Add audit_logs table:
audit_logs(id, actorUserId, action, targetType, targetId, meta JSONB, createdAt)
Log events: role changes, uploads, slide edits, new role creation.
