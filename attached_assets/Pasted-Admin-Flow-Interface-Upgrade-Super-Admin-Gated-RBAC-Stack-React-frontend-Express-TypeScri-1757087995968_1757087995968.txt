Phase 1 — Permissions Model (stay JSON, add schema & registry)
We’ll keep JSON permissions to avoid heavy refactors, but enforce a strict registry so no typos or drift.
Permission registry (server): /server/admin/permissions.ts
Export a read-only list of canonical keys, e.g.:
export const PERMS = {
  users: ['view','edit','ban'] as const,
  roles: ['view','assign','create_custom'] as const,
  trips: ['view','moderate','delete'] as const,
  reports: ['view','resolve','escalate'] as const,
  chat: ['view','moderate','purge'] as const,
  logs: ['view','export'] as const,
  settings: ['view','edit','secrets'] as const,
  taxonomy: ['view','edit'] as const,
} as const;
export type PermDomain = keyof typeof PERMS;
export type PermKey = `${PermDomain}.${typeof PERMS[PermDomain][number]}`;
export const ALL_PERMS: PermKey[] = /* flatten above */;
Schema (Zod) to validate role JSON: only ALL_PERMS allowed.
On startup, validate every role’s JSON. If unknown keys → warn & strip in dev; block in prod.
Role defaults (server):
superadmin: ALL_PERMS
admin: ALL minus settings.secrets, roles.create_custom
moderator: users.view, trips.view,moderate, reports.view,resolve,escalate, chat.view,moderate, logs.view
