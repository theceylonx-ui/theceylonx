You are the lead engineer for Ceylon Expand. Make Pinned and Interested actions durable in the backend so they persist across logout/login and are available for future reference. Do not rely on localStorage for source of truth.
0) Goals
Persist Pinned and Interested actions server-side (Postgres) tied to userId.
Expose APIs to read/write these states and render them on Browse Trips, Calendar, and Dashboard.
Add a compact user_history log for key actions (pin/unpin, interest/withdraw/accept/decline).
Keep idempotent endpoints; no duplicates; safe to re-click.
1) Schema (Drizzle migrations)
Create/ensure these tables & constraints:
-- Pinned trips (durable bookmarks)
pinned_trips (
  userId varchar not null references users(id) on delete cascade,
  tripId varchar not null references trips(id) on delete cascade,
  createdAt timestamp not null default now(),
  primary key (userId, tripId)
);

-- Interest requests already exist; ensure durability & uniqueness
trip_interest_requests (
  id uuid primary key,
  userId varchar not null references users(id) on delete cascade,
  tripId varchar not null references trips(id) on delete cascade,
  status varchar not null check (status in ('pending','accepted','declined','withdrawn')),
  message text null,
  createdAt timestamp not null default now(),
  updatedAt timestamp not null default now(),
  unique (userId, tripId)  -- one live thread per user/trip
);

-- User action history (audit-lite for the user)
user_history (
  id uuid primary key,
  userId varchar not null references users(id) on delete cascade,
  action varchar not null check (action in ('PIN','UNPIN','INTEREST','WITHDRAW','INTEREST_ACCEPTED','INTEREST_DECLINED')),
  tripId varchar not null references trips(id) on delete cascade,
  meta jsonb null,        -- {source:'ui', note:'...'}
  createdAt timestamp not null default now()
);

-- Helpful indexes
create index on pinned_trips(userId);
create index on trip_interest_requests(userId);
create index on user_history(userId, createdAt desc);
2) API (REST, idempotent)
Add/update these endpoints:
# PIN / UNPIN
POST   /api/trips/:tripId/pin          → 204  (upsert pinned_trips)
DELETE /api/trips/:tripId/pin          → 204  (delete pinned_trips)

# LIST USER’S PINNED
GET    /api/user/pins?page=&limit=     → 200 { items:[trip...], total, page, limit }

# INTEREST REQUEST LIFECYCLE (if not already)
POST   /api/trips/:tripId/interest     → 201 { requestId, status:'pending' } (upsert or 409 if already pending)
POST   /api/trips/:tripId/interest/withdraw → 204 (set status='withdrawn')

# USER HISTORY
GET    /api/user/history?page=&limit=  → 200 { items:[{action, tripId, createdAt, meta, trip:{...}}], total, page, limit }
Rules
Require auth for all endpoints above (401 if not logged in).
Idempotency: POST /pin should succeed even if already pinned (no duplicates); return 204.
On each pin/unpin/interest/withdraw/accept/decline event, insert a row in user_history.
3) Services & Guards

createOrGetInterest(userId, tripId, message?)
withdrawInterest(userId, tripId)
Each writes to user_history after success.
Ensure organizer accept/decline flows also append INTEREST_ACCEPTED / INTEREST_DECLINED for the requester.
