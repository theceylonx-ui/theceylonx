MVP bring-up checklist (in order)

Set Replit ↔ domain proxy headers (trust proxy: 1) so secure cookies work behind the proxy.
DB schema hardening (Drizzle)
Convert free-text status/levels to Postgres ENUMs to prevent bad writes:
trip_status_enum ('active','full','completed','cancelled')
difficulty_enum ('easy','moderate','challenging')
Add uniques & FKs:
users.email UNIQUE NULLS NOT DISTINCT
users.googleId UNIQUE, users.facebookId UNIQUE
trips.organizerId → users.id ON DELETE CASCADE
(votes.userId, votableType, votableId) UNIQUE
(ratings.userId, ratings.rateeUserId) UNIQUE
(trip_interest_requests.userId, tripId) UNIQUE
Add indexes where queries hit hardest:
trips(region, date), trips(status), trips ->> 'tags' GIN (use jsonb for tags to leverage GIN), trip_views(tripId), user_interactions(userId, timestamp DESC)
Use soft deletes where needed: deletedAt TIMESTAMP on user-generated content (trips, questions, answers, comments).
Foundational modules
Auth: finish OAuth routes, refresh flow, cookie settings (Secure+SameSite=Lax in prod), session revocation on logout (delete refresh row).
CORS: allow only your frontends; block *.
Rate limiting: per IP+user for auth, trip create, Q&A post.
Validation: Zod schemas for every route; return uniform error shape.

API contracts (crisp examples)
Search trips
GET /api/trips?region=Central&dateFrom=2025-09-10&dateTo=2025-09-20&seats>=2&tags=beach,adventure&page=1&limit=20
→ 200 { items:[{ id, title, fromLocation, toLocation, date, seatsAvailable, price, region, status, tags, difficulty }], total, page, limit }
Post trip
POST /api/trips
{ title, fromLocation, toLocation, date, seatsAvailable, price, region,
  description, tags:[], difficulty, duration, seasonality:[], safetyFlags:[] }
→ 201 { id }
Interest request
POST /api/trips/:id/interest
{ message?: string }
→ 201 { requestId, status:'pending' }
Organizer accepts
POST /api/trips/:id/interest/:requestId/accept
→ 200 { status:'accepted' }
(Emit: notification_events to requester, create/join chat thread)
Personalized recommendations
GET /api/recommendations/personalized
→ 200 { items:[{ tripId, score, factors:{preferences, collaborative, freshness, ...} }] }
Notifications
GET /api/notifications?unread=true
→ 200 { items:[{ id, type, payload, isRead, createdAt }] }

POST /api/notifications/mark-read
{ ids:["...","..."] } → 204
Data model tweaks (worth doing now)
Tags/seasonality/safetyFlags: prefer JSONB + GIN index over text[] for flexible queries:
CREATE INDEX trips_features_idx ON trips USING GIN (features jsonb_path_ops);
Regional taxonomy: create a regions table and constrain trips.region via FK to prevent typos.
Denormalized counters (viewCount, bookingCount): maintain via triggers or a nightly job to avoid write-path contention.
Real-time & scaling notes
Neon serverless + websockets: keep chat payloads lean; consider pg NOTIFY for event nudges (cheap) and fetch details via API.
If you add a queue later, choose a cloud Redis and BullMQ; until then, a lightweight cron worker inside the server is fine.
Deployment gotchas (Replit + custom domain)
app.set('trust proxy', 1) so req.secure is true and cookies get Secure.
Set COOKIE_DOMAIN to .theceylonx.com and only include it in prod.
CORS: exact origins only. Never * with credentials.
Make sure OAuth Authorized redirect URIs exactly match your env (prod vs localhost) and that http vs https is correct.
