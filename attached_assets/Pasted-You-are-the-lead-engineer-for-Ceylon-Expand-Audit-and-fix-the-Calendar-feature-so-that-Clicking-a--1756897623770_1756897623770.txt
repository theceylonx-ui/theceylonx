You are the lead engineer for Ceylon Expand. Audit and fix the Calendar feature so that:
Clicking a date shows that day’s trips (agenda panel).
Filters Pinned / Interested / My Trips / Free work together and persist across navigation.
Performance is snappy and timezone-correct (Asia/Colombo).
Keep changes surgical, backward-compatible, and fully tested.
0) Definitions (source of truth)
Pinned: trips the user bookmarked (pinned_trips or equivalent).
Interested: trips the user has an interest request for (trip_interest_requests where userId = current).
My Trips: trips where organizerId = currentUserId.
Free: trips with status = 'active' and seatsAvailable > 0 (not full/cancelled).
Day click: clicking any calendar cell (month/week/day) selects a local date (Asia/Colombo), queries trips whose start datetime falls within that local day window [00:00, 23:59:59].
1) Backend — API audit & implement
Add/verify endpoint (idempotent):
GET /api/calendar/day
Query: date=YYYY-MM-DD  (local date in Asia/Colombo)
       filters=pinned,interested,my,truly_free  (CSV; optional)
       region?=string
       tags?=CSV
       page?=1
       limit?=20
Behavior:
Convert date (string) to a Colombo-local start/end window.
Build filter predicates:
pinned → join pinned_trips on (userId, tripId)
interested → join trip_interest_requests (status in ('pending','accepted')) for current user
my → trips.organizerId = currentUserId
truly_free → trips.status='active' AND trips.seatsAvailable > 0
Allow multiple filters combined (logical AND across selected filters).
Optional filters: region, tags[].
Return paginated list: { items:[...], total, page, limit }. Redact organizer contacts from payload (use existing redaction util).
Add/verify endpoint for month hydration (optional but recommended):
GET /api/calendar/month
Query: month=YYYY-MM  (e.g., 2025-09)
       summary=true   (if true, return per-day counts only)
       filters=...
Returns:
summary=true → { days:[ { date:'YYYY-MM-DD', count: 3 }, ... ] }
summary=false → paginated full trips within that month.
Indexes (if missing; Drizzle migrations):
CREATE INDEX trips_date_idx ON trips (date);
CREATE INDEX trips_status_idx ON trips (status);
CREATE INDEX trips_seats_idx ON trips (seatsAvailable);
For pinned/interested joins:
CREATE INDEX pinned_trips_user_idx ON pinned_trips (userId);
CREATE INDEX tir_user_idx ON trip_interest_requests (userId, status);
Validation:
Zod-validate query params; clamp limit (max 50).
Enforce auth; anonymous users can still get day trips but user-specific filters (pinned/interested/my) require login; otherwise 401.
