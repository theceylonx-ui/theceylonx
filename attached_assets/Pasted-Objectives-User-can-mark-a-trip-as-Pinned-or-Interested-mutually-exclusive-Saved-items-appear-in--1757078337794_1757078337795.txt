Objectives
User can mark a trip as Pinned or Interested (mutually exclusive).
Saved items appear in Profile → Activity → Saved with filters: All / Pinned / Interested.
When organizer edits a trip → notify all savers (trip_updated with a diff).
When organizer deletes or sets trip inactive/completed → auto-remove from saves and notify (trip_removed or save_removed).
Strong auth (Clerk), optimistic UI, idempotent APIs, and tests.
Data Model (Drizzle)
Create/verify:
Enum
save_type: 'pinned' | 'interested'
trip_status: 'active' | 'inactive' | 'completed' | 'deleted'
Tables
saved_trips
id pk, user_id uuid, trip_id uuid, save_type enum, created_at, updated_at
UNIQUE(user_id, trip_id) to enforce one state per user/trip
Indexes: idx_saved_trips_user, idx_saved_trips_trip
notifications
id pk, user_id uuid, trip_id uuid, type enum: trip_updated | trip_removed | save_removed
payload JSONB (store changed fields), is_read boolean default false, timestamps
Index: idx_notifications_user_unread(user_id, is_read)

Backend (Express + TS)
Auth
Use @clerk/express middlewares withAuth, requireAuth.
Reject writes if user email not verified.
Routes
GET /api/saved?type=all|pinned|interested
Return current user’s saved trips (join minimal trip card fields).
PUT /api/saved (idempotent upsert)
Body: { tripId: string, saveType: 'pinned' | 'interested' }
Upsert on (user_id, trip_id). Returns saved row.
Accept optional Idempotency-Key header and de-dupe within 1 minute.
DELETE /api/saved/:tripId
Remove current user’s save for that trip.
Trip mutations (hook notifications/cleanup in service layer):
PATCH /api/trips/:id (edit) → compute diff on important fields (title, dates, start/end, price, capacity, meeting point, images, description).
If diff not empty → insert notifications for all savers { type:'trip_updated', trip_id, payload:{diff} }.
PATCH /api/trips/:id/status → on inactive|completed|deleted:
Delete rows in saved_trips for trip_id
Insert notifications for affected users:
deleted → trip_removed
inactive|completed → save_removed
DELETE /api/trips/:id (hard) → same as status='deleted' flow.

Guards & Policies
All write routes require: signed-in and email-verified (Clerk check on server + UI check on client).
Organizer-only actions (edit, status, delete) validate ownership.
Rate-limit save toggles per user (e.g., 10/min) to stop spam.
