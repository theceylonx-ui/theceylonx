Title: Add multi-provider sign in (Email, Google, Microsoft, Apple, Phone) with polished UI
Project: Existing Next.js (App Router) site for theceylonx.com using NextAuth.
Goal: Replace current auth with a unified sign-in component that supports:
Type email address and continue (magic link)
Continue with Google
Continue with Microsoft
Continue with Apple
Continue with phone (SMS OTP)
Language: English-only. Keep existing routes/pages intact. Non-authenticated users can browse; posting requires auth.
1) Packages
Keep next-auth v5 (Auth.js).
Add: nodemailer, @auth/core (if needed), twilio for SMS.
If any provider requires it, add uuid.
2) ENV (create/fill)
Add these to .env (or Replit Secrets) and wire in the code:
# NextAuth
NEXTAUTH_URL="https://theceylonx.com"
NEXTAUTH_SECRET="***generate-a-strong-secret***"

# Email Magic Link (Nodemailer – choose one transport)
EMAIL_SERVER_HOST="smtp.yourhost.com"
EMAIL_SERVER_PORT="587"
EMAIL_SERVER_USER="no-reply@theceylonx.com"
EMAIL_SERVER_PASSWORD="***"
EMAIL_FROM="CeylonX <no-reply@theceylonx.com>"

# Google
GOOGLE_CLIENT_ID="***"
GOOGLE_CLIENT_SECRET="***"

# Microsoft (Azure AD single-tenant or common)
AZURE_AD_CLIENT_ID="***"
AZURE_AD_CLIENT_SECRET="***"
AZURE_AD_TENANT_ID="common" # or your tenant

# Apple (Service ID flow)
APPLE_ID="***"               # Services ID
APPLE_TEAM_ID="***"
APPLE_CLIENT_ID="***"        # same as APPLE_ID for Services
APPLE_KEY_ID="***"
APPLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----"

# Phone (Twilio Verify or Messaging)
TWILIO_ACCOUNT_SID="***"
TWILIO_AUTH_TOKEN="***"
TWILIO_MESSAGING_SERVICE_SID="***" # or VERIFY_SERVICE_SID if using Verify
If you prefer Email-only and Google initially, you can leave Microsoft/Apple/Phone vars undefined; the UI should hide unavailable providers automatically.
3) Auth config
Update/create src/lib/auth.ts with providers:
EmailProvider (magic link via Nodemailer)
GoogleProvider
AzureADProvider (Microsoft)
AppleProvider (Services flow)
CredentialsProvider for Phone OTP (pair with Twilio endpoints)
Session strategy: jwt.
Map user email/name/avatar into your User table on first sign-in.
4) Phone OTP flow (minimal, secure)
Create two endpoints:
POST /api/auth/phone/send → accept phone, rate-limit (IP + phone), generate 6-digit code, send via Twilio (Verify or Messaging). Store hashed code + expiry (5 min) in a short-lived table PhoneOtp { id, phone, codeHash, expiresAt, attempts }.
POST /api/auth/phone/verify → accept phone, code; validate, then sign in via CredentialsProvider (attach a stable synthetic email like phone:+9477xxxxxxx@theceylonx.com), create/find User, delete OTP row.
Security/abuse:
Max 3 attempts per code; block for 15 minutes after fail.
Rate-limit sends (e.g., 3 per hour per phone/IP).
5) DB additions (Prisma)
Add PhoneOtp model; migration included.
model PhoneOtp {
  id        String   @id @default(cuid())
  phone     String   @unique
  codeHash  String
  expiresAt DateTime
  attempts  Int      @default(0)
  createdAt DateTime @default(now())
}

Microsoft: use Azure AD app (tenant common for consumer + work/school) and callback https://theceylonx.com/api/auth/callback/azure-ad.
